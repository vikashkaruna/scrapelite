# DatIQ robots.txt
#
# ── Structure ────────────────────────────────────────────────────────────
# ONE wildcard group, then per-bot groups, then the sitemap.
#
# This file previously had TWO `User-agent: *` groups — one near the top with
# the /api/ and /admin disallows, and a second at the bottom repeating only the
# /admin ones. Google merges same-named groups, so it behaved; but the REP spec
# says a crawler picks the single most specific matching group, and a stricter
# implementation would have taken only the LAST one and lost the /api/ disallow
# entirely. There is now exactly one.
#
# A blanket `Allow: /` also makes per-path Allow lines redundant, so the long
# list of individually allowed marketing paths has gone. What is NOT allowed is
# what matters, and that is now the only thing enumerated.
#
# ── What is blocked and why ──────────────────────────────────────────────
# /api/     — JSON endpoints. Nothing to index, and crawling them wastes budget.
# /admin*   — the operator console. PIN-gated, never linked, never in the
#             sitemap. Belt-and-braces: netlify.toml also sends
#             X-Robots-Tag: noindex for it, and index.html rewrites the robots
#             meta client-side, so a crawler ignoring this file still complies.
# the app   — /dashboard, /account, /preview and the rest are the signed-in
#             product, not content. They render the SPA shell, so to a crawler
#             they are near-identical pages with nothing unique on them. Every
#             one also carries X-Robots-Tag: noindex from netlify.toml, which
#             is the real enforcement; these lines just save the crawl.
#
# The private list is kept in scripts/site-routes.mjs as PRIVATE_PREFIXES and
# asserted against this file by scripts/page-ownership.test.mjs.
