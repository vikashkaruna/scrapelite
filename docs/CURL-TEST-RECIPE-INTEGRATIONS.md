## 1. Pre-flight

Before running any curl commands, you need:

### 1a. Apply the 3 new Supabase migrations

Whichever Supabase project the branch deploy points at (you set the env vars
in Netlify — staging or production), the integration tables need to exist.

In the **Supabase Dashboard → SQL Editor → New query**, paste and run each in order:

```sql
\i supabase/migrations/0019_api_keys.sql
\i supabase/migrations/0020_integration_connections.sql
\i supabase/migrations/0021_zapier_events.sql
```

Or paste the auto-generated `supabase/migrations/run-all.sql` once — it has
all migrations in dependency order.

**Verify all 3 tables exist:**

```sql
select table_name from information_schema.tables
where table_schema = 'public' and table_name in
  ('api_keys', 'integration_connections', 'zapier_events');
```

Expected: 3 rows.

### 1b. Confirm env vars are set in Netlify UI

Open the branch deploy's site on Netlify → Site settings → Environment variables.

For the `Integration-with-outside-ecosystem` context (or "All deploys" if you
flipped the filter), verify these are present:

```
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
SUPABASE_URL
SUPABASE_ANON_KEY
SUPABASE_SERVICE_KEY
SUPABASE_ACCESS_TOKEN
```

If any are missing, the integrations will fail at the auth layer.

### 1c. Get your 3rd-party credentials ready

You need a working account + at least a "test" token for each integration you
want to validate:

| Integration | What to get | Where |
|---|---|---|
| **HubSpot** | Private App token (`pat-na1-...`) | HubSpot → Settings → Integrations → Private Apps |
| **Notion** | Internal Integration secret (`secret_...` or `ntn_...`) + a database ID you've shared with the integration | notion.so/my-integrations |
| **Airtable** | Personal Access Token (`pat...`) + a Base ID + a Table ID you've granted the token access to | airtable.com/create/tokens |
| **Slack** | Incoming Webhook URL (`https://hooks.slack.com/services/...`) | Slack → Apps → Incoming Webhooks |
| **Zapier** | (none — the token is generated by DatIQ) | n/a |

Keep these in a notes file or password manager. You'll paste them into curl
bodies below.

## 2. Authenticate + export the SSO cookie

The branch deploy is **SSO-gated** (same as main and staging branch deploys).
Every API request returns 401 until you authenticate.

### 2a. Open the site in a browser and sign in

1. Open `https://integration-with-outside-ecosystem--datiqapp.netlify.app` in
   a private/incognito window.
2. You'll be redirected to:
   ```
   https://app.netlify.com/edge-access?domain=integration-with-outside-ecosystem--datiqapp.netlify.app&requested_path=/&site_id=0ac65a7e-bd3f-4cde-a8d3-66c23899c473
   ```
3. Sign in with the Netlify account that owns the `datiqapp` site.
4. The browser will redirect back to the site. The page should load normally.

### 2b. Export the SSO cookie

**In the browser DevTools:**

1. Open DevTools (F12 or Cmd+Opt+I) → **Application** tab.
2. Under **Cookies** → click `https://integration-with-outside-ecosystem--datiqapp.netlify.app`.
3. Find the `nf_jwt` cookie. Copy its **Value** (it'll be a long JWT string).

**Save it to a shell variable:**

```bash
# In your terminal
export NF_JWT="paste-the-nf_jwt-value-here"
```

**Verify it works** (the API should now respond instead of returning 401):

```bash
curl -sS "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/integrations/hubspot/status" \
  -H "Cookie: nf_jwt=$NF_JWT" | python3 -m json.tool
```

Expected:
```json
{
    "connected": false,
    "provider": "hubspot"
}
```

If you still get 401, the cookie is wrong. Re-export from DevTools.

> **Tip:** the `nf_jwt` cookie lasts ~24 hours. If your tests start returning
> 401 again, re-export from the browser.

### 2c. (Optional) Get a Supabase user session JWT

The `/api/integrations/*` endpoints accept Supabase user JWTs as well (the
Account UI uses them). For curl testing, the SSO cookie is simpler — use that.

If you ever need a real Supabase JWT, the easiest path is to sign in to
DatIQ on the deployed site, then copy the `access_token` from the Supabase
auth client (visible in DevTools → Network tab → any `/rest/v1/...` request
→ Headers → `Authorization: Bearer ...`).

## 7. Slack

### 7.1 Get an Incoming Webhook URL

1. In Slack, **Apps** → search for "Incoming Webhooks" → add to your workspace.
2. Click **Add New Webhook to Workspace**, pick a channel.
3. Copy the Webhook URL: `https://hooks.slack.com/services/T.../B.../XXX...`

### 7.2 Connect

```bash
WEBHOOK_URL="https://hooks.slack.com/services/T00000000/B00000000/XXXXXXXXXXXXXXXXXXXXXXXX"

curl -sS -X POST "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/integrations/slack/connect" \
  -H "Cookie: nf_jwt=$NF_JWT" \
  -H "Content-Type: application/json" \
  -d "{\"webhookUrl\": \"$WEBHOOK_URL\"}" | python3 -m json.tool
```

Expected: `{ "ok": true, "connected": true }`

**Side effect:** a "Welcome to DatIQ" message should appear in your Slack channel
immediately. This is the probe that verifies the webhook works.

If you get `400 channel_not_found`, the webhook was deleted on the Slack side.
If you get `403 action_blocked`, the workspace has a policy blocking incoming
webhooks. If you get `403 invalid_token`, the URL got URL-encoded in transit
(re-paste it; DatIQ validates it starts with `https://hooks.slack.com/`).

### 7.3 Test it

```bash
curl -sS -X POST "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/integrations/slack/test" \
  -H "Cookie: nf_jwt=$NF_JWT" \
  -H "Content-Type: application/json" \
  -d '{}' | python3 -m json.tool
```

Expected: `{ "ok": true }`. A second welcome message should appear in Slack.

### 7.4 Verify in Slack

Open the channel. You should see two "Welcome to DatIQ" messages (one from
the connect probe, one from the test).

## 9. API key

The public REST API uses `dq_live_` bearer tokens. The integration branch
added this; v1.0 didn't have it.

### 9.1 Create a key

```bash
curl -sS -X POST "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/v1/keys" \
  -H "Cookie: nf_jwt=$NF_JWT" \
  -H "Content-Type: application/json" \
  -d '{"label": "Curl test key"}' | python3 -m json.tool
```

Expected:
```json
{
    "ok": true,
    "key": "dq_live_XXXXX...",
    "key_id": "...",
    "label": "Curl test key"
}
```

**Save the key to a shell variable** — the plaintext is returned ONCE:

```bash
DQ_KEY="dq_live_XXXXX..."
```

### 9.2 Extract via the public API

```bash
curl -sS -X POST "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/v1/extractions" \
  -H "Authorization: Bearer $DQ_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://stripe.com/pricing", "intent": "summary"}' | python3 -m json.tool
```

Expected: 200 with the full extraction object.

### 9.3 Verify rate limit (token bucket)

The API has a per-key token bucket. After ~50 requests in 1 minute, you
should see 429 responses. The response includes a `Retry-After` header:

```bash
# Run 60 quick requests to trigger the rate limit
for i in $(seq 1 60); do
  curl -sS -o /dev/null -w "%{http_code}\n" -X POST \
    "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/v1/extractions" \
    -H "Authorization: Bearer $DQ_KEY" \
    -H "Content-Type: application/json" \
    -d '{"url": "https://stripe.com/pricing", "intent": "summary"}'
done | sort | uniq -c
```

Expected: mostly 200, then a few 429s once the bucket runs out.

## 10. Cross-integration drill

This is the full end-to-end test: save one extraction, verify it fans out
to every configured channel.

### 10.1 Make sure all 5 integrations are connected

Re-run the status checks for all 5:

```bash
BASE="https://integration-with-outside-ecosystem--datiqapp.netlify.app"
for p in hubspot notion airtable slack zapier; do
  connected=$(curl -sS "$BASE/api/integrations/$p/status" \
    -H "Cookie: nf_jwt=$NF_JWT" | python3 -c "import json,sys; print(json.load(sys.stdin).get('connected'))")
  echo "  $p: connected=$connected"
done
```

Expected: all 5 should show `connected=True`.

### 10.2 Save an extraction in the UI

1. Open `https://integration-with-outside-ecosystem--datiqapp.netlify.app` in the browser.
2. Type `https://stripe.com/about` into the URL input → click **Extract**.
3. Wait for the extraction to complete (Preview page).
4. From the Preview, click **Push to HubSpot** (and **Push to Notion**, **Push to Airtable** if the buttons are present — they may not be in the UI yet since we're testing via curl, but the API endpoints work).

### 10.3 Verify the fan-out

Check each destination:

| Channel | What to look for |
|---|---|
| **Slack** | A "✅ New extraction: Stripe" message in your Slack channel |
| **Zapier** | A new `new_extraction` event in `zapier_events` table: `select * from public.zapier_events order by created_at desc limit 1;` |
| **HubSpot** | A Stripe company + contacts (only if you triggered the push via UI/API) |
| **Notion** | A new page in your database (only if you triggered the push) |
| **Airtable** | A new record in your base (only if you triggered the push) |

If Slack doesn't fire but the others do, the issue is in `notify.js`'s
Slack channel resolution. Check that your Slack connection is still valid
(step 7.2).

## 11. Cleanup

After testing, you can disconnect all integrations:

```bash
BASE="https://integration-with-outside-ecosystem--datiqapp.netlify.app"
for p in hubspot notion airtable slack zapier; do
  echo "Disconnecting $p..."
  curl -sS -X DELETE "$BASE/api/integrations/$p/connect" \
    -H "Cookie: nf_jwt=$NF_JWT" | python3 -m json.tool
done
```

This deletes the `integration_connections` row for each provider. The 3rd-party
side (HubSpot records, Notion pages, etc.) is unaffected — you'll need to
clean those up directly in the 3rd-party UI if you want.

You can also revoke API keys:

```bash
# List keys
curl -sS "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/v1/keys" \
  -H "Cookie: nf_jwt=$NF_JWT" | python3 -m json.tool

# Revoke a specific key (replace KEY_ID)
curl -sS -X DELETE "https://integration-with-outside-ecosystem--datiqapp.netlify.app/api/v1/keys/KEY_ID" \
  -H "Cookie: nf_jwt=$NF_JWT" | python3 -m json.tool
```
