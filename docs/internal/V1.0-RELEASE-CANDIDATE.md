## 2. What's new in v1.0 (vs the R19 cut)

### 2.1 Home & composer

| Feature | Description |
|---|---|
| **Smart composer** | One composer auto-detects single URL, multi-URL, CSV, or raw text/HTML. Mode badge changes the action button icon (arrow-up / layers / calendar-clock). |
| **Q3 Outcome tiles** | 6 pre-wired intent tiles above the hero (AI summary, Lead list, Pricing, Competitor research, Job board, Custom). Multi-select stacks prompts into a combined extraction. |
| **Q5 Template gallery** | 12 pre-built extraction recipes (YC companies, SaaS pricing, job boards, GitHub repos, etc.) one click from the composer. |
| **Q2 Credit estimator** | Shows the estimated credit cost before you run. Disables Run when over budget. |
| **Trust strip (F14)** | 3-pill trust signal (Encrypted in transit · Auto-deleted in 30 days · Never used to train AI) below the composer. |
| **Q4 In-app onboarding tour** | 7-step tour auto-fires for first-time visitors. Esc to skip. `g t` hotkey to replay. Reduced-motion respected. |
| **Q4 Try-example demo** | 5-step auto-playing walkthrough that types `lumio.io`, picks an intent, and shows a mock extraction. Pause / Replay. |
| **OG preview card** | 800 ms debounce → server-side OG metadata fetch → favicon + title + description preview. |

## 3. Pending production work

### 3.1 Manual Supabase migrations (must run before going live)

These SQL scripts live in `scripts/`. Each is idempotent (`IF NOT EXISTS`).

| Script | Tables created | Notes |
|---|---|---|
| `migrations.sql` | `usage_records`, `usage_alerts`, `subscriptions`, `payment_events`, `pricing_config`, `coupon_redemptions`, `coupon_counters`, `redeem_coupon` RPC | Core V2 + V5 + V5c |
| `ai-config.sql` | `app_config` | Multi-provider AI chain storage |
| `scheduler.sql` | `scheduled_tasks`, `extractions` (base) | R19 recurring runs |
| `analytics.sql` | `analytics_events` | v1.0+ Quick Wins |
| `provenance.sql` | `provenance` (jsonb column on extractions) | v1.0+ Quick Wins |
| `public-reports.sql` | `public_reports` | Q8 shareable URLs |
| `summary-feedback.sql` | `summary_feedback` | F06 feedback widget |

**Order of execution:** `migrations.sql` → `ai-config.sql` → `scheduler.sql` → `analytics.sql` → `provenance.sql` → `public-reports.sql` → `summary-feedback.sql`. None of them depend on each other but `migrations.sql` is the foundation.

### 3.2 Netlify environment variables to set

The full list is in `docs/PRODUCTION-RELEASE-V1.0.md` (this PR). Key sets:

1. **Supabase** — `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`
2. **AI providers** — `GEMINI_API_KEY` (primary), `AI_API_KEY` (Anthropic), `OPENAI_API_KEY`
3. **Scrape providers** — `FIRECRAWL_API_KEY`, `SPIDER_API_KEY` (optional), `JINA_API_KEY` (optional)
4. **Razorpay (INR)** — `VITE_RAZORPAY_KEY_ID`, `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`
5. **Email** — `RESEND_API_KEY`, `ALERT_EMAIL_FROM`
6. **Webhooks** — `VITE_WEBHOOK_URL` (n8n)
7. **Admin** — `ADMIN_PIN_HASH` (sha256 of a strong PIN), `ADMIN_TOKEN_SECRET`

**Critical:** after setting any `VITE_` variable, trigger a full Netlify redeploy — they're baked into the JS bundle at build time.

### 3.6 Known UX caveats (document but don't block release)

- **Q4 Tour auto-fires for first-time visitors** — current behavior is intentional but can feel intrusive. Consider opt-in (button on Home) for v1.1.
- **Annual anchoring** — CTAs say "billed annually" but v1.0 ships one-time Razorpay Orders (not Subscriptions). The discount stack doesn't kick in until v2.0.
- **Trust strip "Auto-deleted in 30 days"** — honest message, actual cron is v2.0 work.
- **Stripe USD** — code paths preserved, switch toggles in v2.0.

## 6. How to roll forward from this branch

1. **Verify the build is green locally:**
   ```bash
   npm install
   npm run test:all
   ```
2. **Open a PR** from `V1.0-Release-Candidate` to `main` (if not already there) — or push directly to `main` if you're ready.
3. **Run the Supabase migrations** in order (see `supabase/migrations/run-all.sql`).
4. **Set Netlify env vars** (see `docs/PRODUCTION-RELEASE-V1.0.md` §3).
5. **Trigger a Netlify redeploy.**
6. **Smoke test the live site** end-to-end against the checklist in `docs/PRODUCTION-RELEASE-V1.0.md` §6.
7. **Tag the release:** `git tag v1.0.0 -m "DatIQ v1.0 — Production release"`.
8. **Publish the release notes** (use this doc as the source).
