### 1. The actual SEO bug (not what the user's Gemini analysis diagnosed)

Gemini's suggested fixes were all already in place — SPA rewrite (`netlify.toml:181`),
JSON-LD, AI-crawler `robots.txt` entries. The real cause: `index.html:12` hard-coded
`<link rel="canonical" href="https://datiq.app/">`, and every SPA-only route (`/privacy`,
`/terms`, `/vs/battlecard`) served that shell verbatim — Google read them as duplicates
of the homepage. That's the "1 indexed, 4 not indexed" in Search Console.

Two more silent instances of the same defect were found while fixing it:
`seoMeta.setMeta()` set `og:url` but never a canonical (og:url carries no
canonicalisation weight — affected `/changelog`, `/gallery`, `/vs/battlecard`, all 6
programmatic pages), and those pages built their URL from `window.location.origin`,
which under the prerenderer is `localhost:4319` — would have shipped a localhost
canonical to production. Both fixed in `src/lib/seoMeta.js` (new `canonicalUrl()` /
`SITE_ORIGIN` helpers).

### 2. One owner per page (`scripts/site-routes.mjs` is the source of truth)

20 URLs used to be served by two different documents (hand-written HTML in `public/`
for cold hits, a React page for in-app nav) and had already drifted — `llms.txt` still
advertised prices the app hadn't charged in months. Now every URL has exactly one
owner:

- **React-owned** (22 routes): authored in JSX, prerendered to `public/<route>/index.html`
  via `npm run prerender` (Playwright + system Chrome), output **committed**, gated by
  a pre-push staleness check — not built on Netlify (a Chromium download failure would
  otherwise fail every deploy).
- **Static-owned**: `/faq`, `/dmca`, `/vs/{browse-ai,clay,firecrawl,apify,phantombuster}`,
  `/help/*` (generated by `docs/build-help.mjs`). Hand-written HTML stays the source;
  no React route exists for these.

`scripts/page-ownership.test.mjs` (23 assertions) encodes the table so it can't drift
silently again.

**Also fixed a live 404**: `BattleCard.jsx` had `<Link to="/vs/firecrawl">` pointing at
a path with no `<Route>` — every in-app click landed on NotFound, direct URL hits
worked fine (static file), so nobody noticed. Its own test only asserted the `href`
string. New `src/__tests__/no-broken-links.test.js` resolves every `<Link to>`/
`navigate()` target against the real route table.

### 3. Consent-gated GA4 (property `G-B0DZLRWG63`)

`public/analytics.js` — one script, loaded synchronously right after `<head>` in
`index.html` and all 44 static pages. Google Consent Mode v2, default **denied**
(pushed before gtag.js loads — order is load-bearing, tested). `runtime-config.js`
must load *before* `analytics.js`: an absent `gaMeasurementId` key falls back to the
built-in id, an *empty string* means deliberately disabled — that distinction is what
keeps staging/branch-deploy traffic out of the production property.

`src/components/ConsentBanner.jsx` — no dismiss-X (ignoring ≠ consent), no monthly
re-prompt. `src/lib/consentService.js` mirrors every choice to
`POST /api/consent` (migration `0023_consent.sql`: `consent_records` + append-only
`consent_audit`, RLS locked to service-role only, `user_id` resolved server-side from
the JWT — never trusted from the body).

`src/hooks/usePageView.js` fires a manual `page_view` per route change — **you already
turned off** GA4's "Page changes based on browser history events" to prevent
double-counting.

### 4. Locked down `analytics_events` (migration `0024_analytics_rls.sql`)

`0005_analytics.sql` had shipped `anon SELECT USING (true)` — the entire in-house
event log (session_id, user_id, arbitrary properties) was readable by anyone holding
the published anon key. Both anon policies dropped; writes now go through
`POST /api/analytics` with the service key. **You've applied both `0023` and `0024`
to dev/staging and prod.**
