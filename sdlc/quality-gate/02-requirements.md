# 02 — Requirements (Phase 1 SDLC output)

> Generated by the `sdlc-datiq-quality-gate` prompt. See `sdlc-prompt.md` for the full prompt.
> All requirements below are **derived from source material** in the repository (CLAUDE.md, `docs/`, `src/`, `netlify/functions/`, `e2e/`, `scripts/`, the existing test files, and the legacy `e2e-test.mjs`). Nothing is invented.

## User story

> A solo engineer (Vikash, maintainer of DatIQ) is shipping a series of small releases (R5 → R19, and counting). Each release adds features, fixes bugs, and touches 10–50 files. The current test suite (8 unit files, 2 Playwright specs, 1 server test, 1 security script) catches some regressions but lets through bugs that are obvious in production: a hard-block modal that doesn't re-mount on reload, a payment-confirm modal that doesn't actually call `initiatePayment`, a retired E2E script that no longer runs in CI, a free-tier trial credit declared in config but never granted. The maintainer needs a release-grade test gate that (a) catches regressions before they ship, (b) scales to R-numbered feature work without being rewritten, (c) runs in CI in under 10 minutes on a free GitHub Actions runner, (d) needs zero live third-party credentials to execute, and (e) gives clear, file:line-anchored evidence when something breaks.

## In-scope

1. New unit tests for all uncovered `src/lib/*.js` files (B.1, ~24 files).
2. New component-level integration tests for `src/components/*.jsx` and `src/pages/*.jsx` that own non-trivial behaviour (B.2, ~25 files).
3. New contract tests for every `netlify/functions/*.js` and `netlify/functions/lib/*.js` (B.3, ~21 files).
4. New functional page tests for all 18 routes (B.4).
5. New system tests that mount the real provider tree (B.5, 6 files).
6. Port the 89 checks from the retired `e2e-test.mjs` into Playwright smoke specs (B.6, 23 files / ~80 assertions).
7. New Playwright journey specs covering multi-step user flows (B.7, 10 files / ~60 assertions).
8. New security tests beyond the secret-pattern script (B.8, 4 files).
9. New accessibility tests via `vitest-axe` (component) and `@axe-core/playwright` (page) (B.9, 7 files).
10. New visual-regression snapshots for the 8 stable public pages (B.10, 8 files).
11. CI integration: extend `.github/workflows/quality-gate.yml` so the new tests run on every PR + push to `main`, and the report lands in PR checks.
12. Five high-priority implementation fixes from C.5, C.7, C.8, C.13, C.18, each with its own test.
13. Documentation updates: JSDoc on `useToast`, an ESLint config (I-1), refresh of `AGENTS.md` testing section.

## Out-of-scope

- **TypeScript adoption** (D.2 II-1) — too large for this initiative; we add `// @ts-check` JSDoc to one service as a stepping stone.
- **Real provider integration tests** (D.2 II-3) — the offline-mock boundary is preserved; we do not call Firecrawl/Spider/Jina/Stripe/Razorpay/Supabase from tests.
- **Cross-browser matrix** (D.2 II-9) — chromium-only for now.
- **Lighthouse CI** (D.2 II-4) — separate initiative.
- **Bundle-size budget** (D.2 II-5) — separate initiative.
- **Storybook** (D.2 II-2) — separate initiative.
- **PWA / mobile-app shell** (D.2 II-10) — out of product scope.
- **Migration to a new test runner** — we keep Vitest + Playwright.
- **DPDP-specific data-handling tests** — Privacy.jsx is a static page; the server-side privacy boundary is already enforced by Supabase RLS, which we test via contract tests on the data-plane functions.
- **Stripe live integration** — Razorpay is the live provider; Stripe is wired but not used.

## Non-functional requirements

| NFR | Target |
|---|---|
| **NFR-1 — Test runtime** | Full `npm run test:all` SHALL complete in < 10 min on a free GitHub Actions ubuntu-latest runner. The new tests add at most 3 min to the current ~5 min. |
| **NFR-2 — Coverage** | `src/lib/*.js` line coverage ≥ 80 % (up from 70 % on 6 files). `src/components/*.jsx` line coverage ≥ 60 %. `src/pages/*.jsx` line coverage ≥ 50 % (via functional + integration tests, not unit). |
| **NFR-3 — Determinism** | No test SHALL rely on real network, real API keys, real timers (`setTimeout`/`Date.now`), or `crypto.randomUUID`. The existing offline-mock boundary is preserved. |
| **NFR-4 — Independence** | Each Vitest file SHALL be runnable in isolation (`vitest run src/lib/foo.test.js`) and SHALL clear `localStorage`/`sessionStorage` in `beforeEach` (already in `test/setup.js`). |
| **NFR-5 — Accessibility target** | Axe-core SHALL report zero "serious" or "critical" violations on every audited component and page. |
| **NFR-6 — Security** | `test:security` continues to fail the build on any tracked-file secret pattern or high/critical `npm audit` finding. New functional security tests SHALL fail the build on bypass. |
| **NFR-7 — Browser support** | Chromium only for Playwright (matches current config). jsdom for Vitest (already configured). |
| **NFR-8 — i18n / l10n** | Test inputs SHALL NOT assume `en-US` only. Currency tests cover both `en-IN` and `en-US`. Date tests use `Intl.DateTimeFormat`. |
| **NFR-9 — Performance budget** | A failed visual-regression test SHALL not push CI over 10 min. |
| **NFR-10 — Documentation** | `AGENTS.md` testing section SHALL be updated to reference the new test files, commands, and the new ESLint config (I-1). |
| **NFR-11 — Backwards compatibility** | No production behaviour SHALL change as a result of adding tests. The five implementation fixes (FR-Z-01..05) are the only behaviour changes; each is gated by a test. |

## Acceptance criteria

### AC-U (sample, one per layer)

- **AC-U-06 (FR-U-06):** Given `usageService.readUsage` returns `{ month: "2026-07", extractions: 99, ... }` and the plan is `select` (limit 100), when `canExtract("select")` is called, then `{ allowed: true, remaining: 1 }`. Given `extractions: 100`, when `canExtract("select")` is called, then `{ allowed: false, remaining: 0, reason: "Your Select plan allows 100 extractions / month..." }`. Given `extractions: 100, bonusExtractions: 50`, then `{ allowed: true, remaining: 50 }`. Given `month` is the previous month, when `readUsage` is called, then the new month starts at 0 (rover).

- **AC-I-03 (FR-I-03):** Given `datiq.guestTrial = { count: 3, batchCount: 0 }` and a fresh `GuestTrialProvider` mount, when the user attempts a 4th extraction, then `showSoftPrompt` becomes `true` and the modal renders with "Sign up free" + "Continue as guest" buttons. Given the user clicks "Continue as guest", the count stays at 3 and the prompt hides. Given a 5th extraction, the prompt re-shows. Given `count: 10`, on page reload the hard-block modal mounts immediately.

- **AC-C-04 (FR-C-04):** Given a request to `create-checkout` with `{ plan: "pro", currency: "INR", billingPeriod: "annual" }` and `couponCode: "EXPIRED"`, when the function resolves pricing, then the order amount is `pro.price_inr_annual × 12 × 1.18` paise, no coupon is applied, and the response is `{ orderId, amount, currency: "INR" }`. Given a valid coupon, the discount is `min(coupon, global)`.

- **AC-S-01 (FR-S-01):** Given a logged-in user with `datiq.saved` and `datiq.guestTrial.count = 4`, when `useAuth.signOut()` is called, then `datiq.saved`, `datiq.current`, `datiq.enrichments`, and the 4 other sensitive keys are removed, `datiq.guestTrial` is preserved, and the URL is `/`.

- **AC-J-01 (FR-J-01):** Given the offline-mock boundary, when the user navigates `/` → fills URL → clicks Extract → /preview loads → clicks "Find Contact Info" → reloads → re-activates the tab → clicks "View Dashboard" → searches "analytics" → selects the row → clicks Export ▾ → CSV, then a CSV file is downloaded with at least 5 rows (meta + heading + link + mapped-url + enrichment) and the file parses without error.

- **AC-K-01 (FR-K-01):** All 23 smoke specs pass on every PR. The Playwright HTML report uploads on any failure. The smoke suite completes in < 60 s.

- **AC-A-05 (FR-A-05):** AuthModal renders with no axe-core "serious" or "critical" violations when measured with `vitest-axe`.

- **AC-V-01 (FR-V-01):** A fresh capture of `/` at 1280×800 light matches `e2e/visual/__snapshots__/home-light-1280.png` byte-for-byte (Playwright `toHaveScreenshot` allows the default 0.2 % pixel diff).

- **AC-X-03 (FR-X-03):** A request to `create-checkout` with `{ plan: "pro", currency: "INR", discountPercent: 99 }` SHALL ignore the client field and apply the server-computed discount only.

- **AC-Z-01 (FR-Z-01):** Given the DemoPaymentModal flow is wired (FR-Z-01 fix), when the user clicks "Confirm & Pay" inside PaymentConfirmModal, then `initiatePayment` is called exactly once and the plan upgrades.
